# 官方终端、浏览器与对话

工作台复用 DeepSeek Harness 的终端和浏览器服务，分别由官方控制器和官方右侧栏管理。

## 终端

- 官方 `ClientTerminals` 管理终端进程、恢复和输入控制；工作台保存当前 Session 的终端标签与布局。
- 折叠终端或切换工作区不会主动结束进程；关闭终端时由官方控制器回收进程。
- 旧版自建终端进程不能迁移到官方控制器。升级后请新建终端。
- 不再使用自建终端 API，也不依赖 `node-pty`。

## 浏览器

- 浏览器启动页、网页和导航均留在 Harness 官方右侧栏。工作台通过官方打开 API 请求页面，不创建浏览器编辑器标签，也不搬动或改写官方页面 DOM。
- 从工作台打开的链接及 HTML 预览按设置中的默认浏览器处理；选择系统浏览器时交给系统打开。
- 切换 Session 或取消打开请求时，旧请求不会延迟打开到新会话。
- 不接入 Agent 浏览器。

## 原生侧栏过渡

工作台对话栏关闭时，首次打开官方右侧栏会直接展示最终布局，避免过渡期间露出隐藏的对话内容。对话栏已显示时仍保留官方动画；该布局处理不影响浮动工作台和官方终端浮窗。

相关回归位于 `tests/dsh/native-browser.spec.ts` 和 `tests/dsh/native-sidebar.spec.tsx`。CI 运行类型检查、完整测试和构建；桌面实测与自动化测试代表不同的验证范围。

## DSH 对话

- 默认保留工作台原有对话栏，不自动打开侧栏对话。会话标题栏的图标操作可显式在工作台与官方侧栏之间切换；侧栏标签使用官方拖动、分屏、浮动和全屏能力。
- 对话操作图标注册在官方会话标题栏工具区，与官方控件保持同一行；官方「…」菜单继续提供对应操作。侧栏收起、切换标签或移动对话时，官方会话继续管理草稿、附件与生成状态，工作台按会话恢复阅读位置。
- 同一会话的输入框只由当前显示的对话使用。资源引用、SSH 目标与 AI 改动审阅跟随该对话。
